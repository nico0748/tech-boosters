# はじめに

XでClaudeの使い方を紹介している方って、$200の上位プランの人が多い気がするんですよね。逆に、料金を気にしてProを使っている人のほうが一般的には多そうで、その間の **Max（Proの5倍）** を使っている人の投稿は少ないなと思ったので、自分の使い方をまとめてみました。

# この記事でわかること

- Maxプランで何が増えるのか（2026年11月9日時点の公式情報）
- 1か月で59スレッド立てた、記事と図の並列づくりの運用
- 語調や図のルールを「スキル」にして毎回説明しなくて済むようにする工夫
- 作業ごとのモデルの使い分け

# Maxプランってどんなプラン？

まずは公式情報で、プランの中身を確認しておきます。料金やプラン名はよく変わるので、以下は **2026年11月9日時点** の[料金ページ](https://claude.com/pricing)と[ヘルプセンター](https://support.claude.com/en/articles/11049741)の内容です。

| プラン | 月額（米ドル） | 利用枠 |
|---|---|---|
| Pro | $20（年払いなら月$17相当） | Freeより多い（5時間ごと・週ごとに上限あり） |
| Max | $100 | Proの5倍（5時間ごと・週ごとに上限あり） |
| Ultra | $200 | 5時間ごとの上限なし（認証済みアカウント）、週の上限はProの10倍 |

:::note info
少し前までは、$100のプランが「Max 5x」、$200のプランが「Max 20x」と呼ばれていました。いまの料金ページでは、$100のプランは単に「Max」、$200のプランは「Ultra」という名前になっています。この記事の「Max（5x）」は$100のプランのことです。
:::

Maxでできることのうち、私の使い方に関係するものを抜き出すとこうなります。

- **上限は5時間ごとと週ごとの2段構え**：5時間ごとの上限はセッション単位でリセットされ、別に週の上限があります。週の上限のリセット時刻はアカウントごとに決まっています
- **Web・デスクトップ・モバイル・Claude Codeで枠は共通**：どこで使っても同じ利用枠から引かれます
- **Claude Codeが使える**：ターミナルやクラウドでコードを書いたり、ファイルを操作したりできます
- **Fableは週の上限の半分まで**：MaxではFableモデルを、週の上限の半分まで使えます（Proでは使った分だけ利用クレジットで払う形）
- **APIクレジットが毎月付く**：料金ページでは「月$100分のAPIクレジット」と書かれています
- **上限に達したら利用クレジットで続けられる**：オンにすると、標準のAPI料金で使い続けられます

ちなみに、上限に達するまでの速さは「使うモデル・会話の長さ・ファイルの大きさ」で変わると公式に書かれています。メッセージ何通まで、という固定の数字は出ていません。

# 記事づくりを1つの「プロジェクト」にまとめる

いまの使い方の中心は、Qiitaの記事づくり用に作った1つのプロジェクトです。

【要Nico確認：この機能の正式な名前と、使っている画面（Webかデスクトップアプリか）】

プロジェクトには窓口のチャットがあって、「〇〇の記事を書いて」「compact no.20の図を作って」と頼むと、作業ごとに別のスレッドが立ちます。スレッドはそれぞれ独立して動くので、記事の下書きと図の作成を同時に何本も進められます。

どのくらい使っているのか、2026年11月9日時点で数えてみました。

| 項目 | 数 |
|---|---|
| プロジェクトを作ってからの期間 | 2026年10月10日〜11月9日（約1か月） |
| 立てたスレッド | 59本 |
| 1日で一番多く立てた日 | 22本（11月7日） |
| リポジトリにある記事の下書き | 54本（compact 33本、other 18本など） |
| そのうちQiitaに公開した記事 | 11本 |

一番多かった日は、compactシリーズの図をno.11〜no.24まで1本ずつスレッドにして14本を一気に立て、そのあと記事や図のスレッドを8本追加しています。22本とも、最初のスレッドを立ててから25分ほどのあいだに立てたものです。

並列で回すときに効いているのは、次の2つです。

- **プロジェクトのメモリ**：「図は横2000pxのPNGにする」「深ぼり隊のタイトルは『〇〇を深ぼってみる』」といったルールを、どのスレッドからも読めるメモリに残しています。新しいスレッドを立てるたびに説明し直さなくて済みます
- **共有フォルダ**：スレッド同士で、下書きや図のファイルを同じ場所に置いて受け渡せます

記事以外でも、ライブコーディング面接の練習アプリ（LCI）の開発を同じプロジェクトのスレッドでやっていました。

# 語調と図のルールを「スキル」にする

記事の語調は、私の趣味垢の投稿418件から語尾や絵文字の使い方を抜き出して、スキル（Claudeに読ませる手順書）にしています。技術的な説明は平易に書いて、個性は導入やまとめだけに出す、という配分もスキルに書いてあります。

図も同じで、図解のルール（図の種類ごとの描き方、配色、文字サイズなど）をまとめたスキルを使っています。PPTXで作ってPNGに書き出す、図の中にタイトルを入れない、長い文を入れない、といった私のルールはメモリ側に置いています。

一度スキルにしてしまえば、「いつもの感じで」で通じるのがかなり楽です。

# 図はサブエージェントに批評させる

図は、1回作って終わりにはしていません。サブエージェント（作業を分担する別のClaude）を並列で立てて、見やすさ・長い文が入っていないか・文言が体言止めになっているか、といった観点で批評させて、直す、を何周か回しています。

# Macのフォルダに直接書き込んで、GitHubから公開する

できあがった下書きや図は、Macの記事用フォルダに直接書き込んでもらっています。記事のリポジトリはGitHubで管理していて、`main` にマージするとGitHub ActionsでQiitaに投稿される仕組みです。

公開だけは取り消しが効かないので、マージは必ず自分でOKを出してからにしています。

# モデルはどう使い分けているか？

作業ごとに、モデルをこう使い分けています。

| 作業 | モデル |
|---|---|
| 開発 | Opus 5.5 |
| セキュリティ関連 | Opus 4.8 |
| Googleカレンダーへの予定登録 | Sonnet 5.5 |
| Fable | あまり使っていない |

開発はいちばん新しいOpus 5.5に任せています。

セキュリティ関連だけOpus 4.8にしているのは、私の体感ではOpus 5.5だとアラートが出ることが多かったからです…（泣）。脆弱性や攻撃手法を扱う記事を書いていると、どうしてもそういう話題が増えるので、いまはこの分け方に落ち着いています。

Googleカレンダーへの予定登録のような、やることがはっきりしている作業はSonnet 5.5で十分なので、軽いモデルに回しています。

Fableは、Maxなら週の上限の半分まで使えるのですが、いまのところあまり出番がないです。

# まとめ

- Maxは$100で、Proの5倍の利用枠が5時間ごと・週ごとに付くプラン（2026年11月9日時点）
- 枠はWeb・アプリ・Claude Codeで共通なので、どこで使っても同じ財布から出ていく
- 記事づくりは1つのプロジェクトにまとめて、1か月で59スレッドを並列で回した
- 語調や図のルールはスキルとメモリに置いて、毎回の説明を省いている
- モデルは開発・セキュリティ・定型作業で使い分けている
- 公開（マージ）だけは自分の手でやる

同じMax（5x）ユーザーで、もっといい使い方をしている方がいたら、ぜひ教えて欲しいです！
