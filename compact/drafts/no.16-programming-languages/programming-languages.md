# はじめに

言語の紹介でよく出てくる「静的型付け」「コンパイル言語」「GC あり」を、1つの表で見比べられるようにまとめておきます。

# ひとことで言うと

**プログラミング言語は、人が書いたやりたいことを、コンピュータが実行できる形にするための言葉**です。
言語どうしは、次のいくつかの軸で比べると違いが分かりやすくなります。

| 軸 | 選択肢 |
|---|---|
| 実行のしかた | 事前にコンパイル / インタプリタ / 中間コード＋仮想マシン |
| 型付け | 静的型付け / 動的型付け |
| メモリの管理 | 手動 / ガベージコレクション（GC） / 所有権 |
| パラダイム | 手続き型 / オブジェクト指向 / 関数型（多くの言語は複数に対応） |

# 実行のしかた

| 方式 | 中身 | 例 |
|---|---|---|
| 事前コンパイル | 実行する前に、機械語に変換しておく | C、C++、Rust、Go |
| インタプリタ | 実行しながら、1行ずつ（または少しずつ）解釈する | bash などのシェルスクリプト、Ruby（1.8 までの処理系） |
| 中間コード＋仮想マシン | バイトコードに変換して、仮想マシンで動かす。実行中に機械語へ変換（JIT）することも多い | Java、C#、Python、JavaScript、Ruby、PHP |

厳密には、これは言語ではなく**実装（処理系）**の性質です。たとえば Python にも、JIT で動く処理系（PyPy）があります。

# 型付け

| 方式 | 中身 | 例 |
|---|---|---|
| 静的型付け | 実行する前に、型の間違いを見つける | C、Java、Go、Rust、TypeScript |
| 動的型付け | 実行してみて、型の間違いが分かる | Python、Ruby、JavaScript、PHP |

最近は、動的型付けの言語に型ヒントをつけて、事前にチェックする使い方も広がっています（Python の型ヒント、TypeScript）。

# メモリの管理

| 方式 | 中身 | 例 |
|---|---|---|
| 手動 | 確保と解放を自分で書く | C、C++ |
| GC | 使わなくなったメモリを、実行時に自動で回収する | Java、Go、Python、JavaScript |
| 所有権 | 誰がメモリを持っているかのルールを、コンパイラがチェックする | Rust |

# セキュリティから見ると

- C や C++ では、バッファオーバーフローや解放後使用（use-after-free）などのメモリの脆弱性が起きやすい
- そのため、米国の CISA や NSA は、Rust や Go などの**メモリ安全な言語**への移行を勧めている

# まとめ

言語は「好き嫌い」だけでなく、実行方式・型・メモリ管理の軸で見ると、向き不向きが見えてくるのよ。
ほかにも大事な比べ方があれば、有識者の方教えて欲しいです！
