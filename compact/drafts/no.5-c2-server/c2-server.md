# はじめに

ニュースで「C&Cサーバと通信していた」とよく見るけど、具体的に何をしているのかをまとめておきます。

# ひとことで言うと

**C&C（Command and Control、C2）サーバは、攻撃者がマルウェアに感染した端末へ命令を送り、結果を受け取るためのサーバ**です。

# 何をしているのか

感染した端末（ボット、エージェント）は、C&Cサーバと次のようなやり取りをします。

1. 感染した端末が、C&Cサーバに定期的に接続する（ビーコン）
2. C&Cサーバが命令を返す（コマンドの実行、ファイルの取得、ほかの端末への横展開など）
3. 端末が命令を実行し、結果や盗んだデータを送り返す

外から内への接続はファイアウォールで止められやすいので、**端末の側から外へ接続しにいく**形が多いです。

# 通信の隠し方

| 手口 | 中身 |
|---|---|
| ふつうの Web 通信にまぎれる | HTTP / HTTPS でやり取りし、ふつうの閲覧に見せかける |
| DNS を使う | DNS の問い合わせや応答にデータを埋め込む |
| 正規のサービスを使う | クラウドストレージや SNS、チャットツールを中継に使う |
| DGA（ドメイン生成アルゴリズム） | 接続先のドメインを日ごとに自動生成し、ブロックされにくくする |

# 構成の種類

| 構成 | 中身 | 弱点 |
|---|---|---|
| 集中型 | 1か所（または少数）のサーバがすべての端末に命令する | サーバを止められると全体が止まる |
| P2P 型 | 感染端末どうしで命令を中継する | 作りが複雑になる |

# 守る側から見ると

- 決まった間隔で同じ宛先に通信している端末は、ビーコンの可能性がある
- 脅威インテリジェンスで共有されている C&C のドメインや IP アドレスと突き合わせる
- 警察やセキュリティ企業が C&Cサーバを差し押さえたり、ドメインを乗っ取って無害なサーバに向けたり（シンクホール）して、ボットネットを止めることがある

# 正規のレッドチーム用途

ペネトレーションテストやレッドチーム演習では、許可を得た範囲で C2 フレームワーク（Cobalt Strike、Sliver、Mythic など）を使います。
同じ仕組みを、守る側が攻撃を再現して対策を確かめるために使っている、ということです。

# まとめ

C&Cサーバは「感染端末の司令塔」で、守る側は「端末から外への怪しい定期通信」を見つけるのが鍵なのよ。
ほかに有効な検知のしかたがあれば、有識者の方教えて欲しいです！
