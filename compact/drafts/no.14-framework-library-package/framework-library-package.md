# はじめに

「React ってフレームワーク？ライブラリ？」で毎回迷うので、3つの言葉の違いをまとめておきます。

# ひとことで言うと

| 言葉 | ひとことで | 主導権 |
|---|---|---|
| ライブラリ | 便利な機能の詰め合わせ。**自分のコードが呼ぶ** | 自分のコード |
| フレームワーク | アプリの骨組み。**自分のコードがフレームワークに呼ばれる** | フレームワーク |
| パッケージ | コードを配ったり入れたりするための**単位（箱）** | — |

ライブラリとフレームワークは「中身の役割」の話で、パッケージは「配り方」の話です。軸が違うので、「パッケージとして配られているライブラリ」のように重なります。

# ライブラリとフレームワークの違い

いちばん分かりやすい見分け方は、**どっちがどっちを呼ぶか**です。

- ライブラリ：処理の流れは自分で書き、必要なところでライブラリの関数を呼ぶ
- フレームワーク：処理の流れはフレームワークが持っていて、決められた場所に書いた自分のコードを、フレームワークが呼ぶ

この「呼ぶ側と呼ばれる側が逆になる」ことを、**制御の反転（Inversion of Control）**と呼びます。

```python
# ライブラリ：自分のコードが requests を呼ぶ
import requests
res = requests.get("https://example.com")

# フレームワーク：自分が書いた関数を、Flask がリクエストのたびに呼ぶ
from flask import Flask
app = Flask(__name__)

@app.route("/")
def index():
    return "hello"
```

| 種類 | 例 |
|---|---|
| ライブラリ | NumPy、requests、lodash、React（公式は「ライブラリ」と名乗っている） |
| フレームワーク | Django、Flask、Ruby on Rails、Spring、Next.js |

# パッケージ

コードをまとめて配布・インストールするための単位です。言語ごとに、パッケージを置く場所（レジストリ）と、入れる道具（パッケージマネージャ）があります。

| 言語 | レジストリ | パッケージマネージャ |
|---|---|---|
| JavaScript | npm レジストリ | npm、pnpm、yarn、bun |
| Python | PyPI | pip、uv など |
| Ruby | RubyGems | gem、Bundler |
| Rust | crates.io | Cargo |

Python では「パッケージ」が2つの意味で使われるので注意が必要です。

- 配布の単位（`pip install` で入れるもの）
- `import` できる、モジュールをまとめたディレクトリ

# まとめ

「呼ぶのがライブラリ、呼ばれるのがフレームワーク、配る箱がパッケージ」と覚えておけば、だいたい迷わないのよ。
この分け方でしっくりこない例があれば、有識者の方教えて欲しいです！
